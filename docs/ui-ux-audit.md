# nothing.ai — UI/UX Audit

_Audit date: 2026-06-24. Scope: full landing page (Next.js 16, dark "phosphor" terminal aesthetic) ahead of the social marketing push._

Overall verdict: the page is genuinely well-built — WCAG-tuned color tokens, `focus-visible`
rings everywhere, reduced-motion handling, a skip link, semantic landmarks, 44px touch
targets, and source-attributed analytics. The items below are refinements, not rescues.

---

## ✅ Done (2026-06-24)

### 1. Social share image (OG/Twitter card) — _was 🔴 critical_
Shared links rendered as bare text cards with no image. Fixed:
- `app/opengraph-image.tsx` — 1200×630 card generated by `next/og` at build time
  (ring+dot mark, phosphor `.ai`, headline, subline, "founding access · 50% off" hook).
- `app/twitter-image.tsx` — re-exports the same art so X gets a real `twitter:image`.
- `app/layout.tsx` — added `metadataBase` + `openGraph.url`/`siteName` for absolute URLs.
- Verified live on trynothingai.com (full tag set; `/opengraph-image` → `200 image/png`).
- Commit `8022816`, deployed to production.

### 2. Sticky-bar signups now tracked — _was 🔴 critical_
`StickyWaitlistBar` POSTed to `/api/waitlist` but never called `capture()`, so its
conversions were invisible in PostHog. Fixed: now fires
`waitlist_signup` with `{ source, location: 'sticky_bar', has_context: false }` on success.
- Commit `8022816`, deployed.

## ⬜ Remaining — pick up here

### 3. Sticky bar swallows errors silently — 🟡 should-fix
On any failure it does `setState('idle')` — including the **429** from the Upstash rate
limiter. The field clears, nothing happens, no message → users assume success or breakage.
The `WaitlistSection` form already handles this correctly (`role="alert"` + message text);
make the sticky bar match (add an `'error'` state + visible message).
File: `components/StickyWaitlistBar.tsx`.

### 4. Hidden sticky bar is still keyboard-reachable — 🟡 should-fix (a11y)
It hides via `transform: translateY(100%)` with `aria-hidden`, but the email input and
buttons stay in the tab order off-screen — a keyboard user can Tab into an invisible form.
Fix: add the `inert` attribute (or toggle `visibility: hidden`) when `!show`.
File: `components/StickyWaitlistBar.tsx`.

### 5. Two email fields visible at once — 🟡 should-fix
When you scroll to the `#waitlist` section the sticky bar is also showing, so the bottom of
the page has two competing email inputs. Hide the sticky bar when the main waitlist section
enters the viewport (IntersectionObserver on `#waitlist`).
Files: `components/StickyWaitlistBar.tsx` (+ observe `WaitlistSection`'s `#waitlist`).

### 6. CTA label casing is inconsistent — 🟢 polish
Deliberate lowercase brand voice (`join waitlist`, footer, taglines) but buttons mix it:
`Get founding access` (Title), `Skip the line` (section) vs `skip the line` (hero),
`Be first.` / `you're in.` Pick one rule — recommend keeping headlines/sentences
capitalized and making all **button labels** lowercase to match the nav.
Files: `Nav.tsx`, `HeroWaitlistInline.tsx`, `WaitlistSection.tsx`, `StickyWaitlistBar.tsx`.

### 7. `app/favicon.ico` is almost certainly the stock create-next-app icon — 🟢 polish
Modern browsers use the SVG (`/nothing-favicon.svg`), but older browsers and some social
scrapers fall back to the `.ico` → they'd show the Next.js logo. Generate a real one from
`public/nothing-favicon.svg` (there's already a TODO in `app/layout.tsx`).

### 8. Dead default assets in `public/` — 🟢 housekeeping
`next.svg`, `vercel.svg`, `globe.svg`, `window.svg`, `file.svg` are leftover create-next-app
files sitting in the **public** repo. Harmless but sloppy — delete them.

### (bonus) Copyright at `opacity: 0.4` on `--ghost2` — 🟢 minor
Likely dips below contrast minimums. Fine as decoration; flagging only.

### (bonus) Next 16 deprecation — unrelated to UX
Build warns `middleware.ts` should be renamed to `proxy.ts` (the vanity-link redirector).
Still works; worth doing eventually.
